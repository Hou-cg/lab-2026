### 今天学到的知识点（这些是核心）

1. **`.py` 文件和 `>>>` 交互模式不一样**：
   - `>>>` 里敲表达式会**自动显示**结果；
   - `.py` 文件里**只计算、不显示**，必须用 `print` 才会输出。

2. **不报错也不输出**，说明"电脑照做了，但没东西可做"——要去检查输入（比如有没有 `print`、文件是不是空的）。
   **报错**则是"看懂了但做不了"——看报错最后一行找原因。

3. **Python 代码里的标点必须是英文半角**：中文的冒号 `：`、引号 `"`、括号 `（）` 都会导致 `SyntaxError`。打字前先确认输入法是英文。

4. **缩进是语法，不是排版**：Python 用缩进表示代码的层次归属。`else` 必须和 `if` 对齐在同一列。

5. **Python 是"先通读整个文件、再执行"**：只要有一处语法错，整个文件都跑不起来（跟 `>>>` 的"边敲边执行"不同）。

6. **`=` 和 `==` 是两回事**：`=` 是赋值（装进盒子），`==` 是判断相等（问是不是）。

7. **列表下标从 0 开始**；`-1` 表示最后一个；切片 `a[0:3]` 是"**左含右不含**"。

8. **循环变量在循环结束后依然存在**，值是最后一次循环的值；如果循环因报错没执行，这个变量就不存在，会报 `NameError`。

9. **函数**：`def` 定义、括号里是**参数**（入口）、`return` 是**返回值**（出口）。
   - `return` 负责"把结果递出来"，`print` 负责"把结果贴出来"——**递出来 ≠ 贴出来**。
   - 函数内部用 `return` 的，外面调用时通常要套一层 `print` 才看得到结果。

10. **变量名不能和 Python 内置名字重名**（`max`、`min`、`sum`、`list` 等），否则会覆盖内置函数，留下隐患。我把 `max` 改成了 `max_value`。

11. **`/` 是精确除法**（`31/8 = 3.875`），`//` 是整除（`31//8 = 3`）。

12. **字典 = 一排"贴了标签的抽屉"**：
    - 取值：`d["a"]`
    - 加值 / 改值：`d["b"] = 2`（标签不存在就新建，已存在就替换）
    - 有没有：`"b" in d`

13. **"先猜、再跑、再对比"** 是最有效的练习方法——它逼你在脑子里真的运行一遍代码。

def hex_to_rgb(s):

    g = int(s[2:4], 16)
    b = int(s[4:6], 16)
    return (r, g, b)
```

### 2. 关键理解

- **编码 = 打包**（`.ppm` → `.okti`）；**解码 = 拆包**（`.okti` → `.ppm`）
- OKTI 文件结构：第 1 行 `okti` / 第 2 行「宽 高」/ 之后按逐行扫描顺序描述像素
- 四种写法：`p`（完整 RGB，6 位十六进制）/ `d`（与上一个像素的差值，每位偏移 8）/ `r`、`R`（重复，1 位 / 2 位）/ `i`、`I`（颜色表索引，1 位 / 2 位）
- **编码优先级：`r` → `i` → `d` → `p`**（能用短的就不用长的）
- `rN` 表示「额外再复制 N 个」，**覆盖 N 个像素**（不是 N+1）
- 颜色表：最多 256 项；新颜色插到最前；已存在则不重复插入；超出丢最后一项；初始含黑色

### 3. 踩到的坑与解决

| 现象 | 原因 | 解决 |
|------|------|------|
| 编码器输出的颜色错、像素数也不对 | 遇到重复像素时直接写 `r`，**没有先用 `p` 写出当前像素**，导致 `r` 复制了更早的颜色、当前像素被漏掉 | 改为「先用 `p` 写当前像素 → 再写 `rN` 追加后面的」 |
| AI 提到的「课程提供的 .okti 期望文件」并不存在 | AI 为了让方案完整而虚构资源 | 核实后改用「**往返测试**」来验证 |

 │     ├── skip_whitespace_and_comments
 │     └── read_ppm_token
 └── save_okti
       └── encode_pixels
             ├── run_token                    (r / R)
             ├── color_index → index_token    (i / I)
             ├── is_difference_allowed → difference_token   (d)
             └── full_pixel_token             (p)
```

`encode_pixels` 下面的四个分支，**正好就是「编码优先级 r → i → d → p」在代码里的体现**。

### 4. 学到的关键区别

- **`.ppm` 里：「每 3 个数字 = 1 个像素」**（二进制文件，每个通道是 1 个 0~255 的数字）
- **`.okti` 里：「每 6 个字符 = 1 个像素」**（文本文件，每个通道写成 2 位十六进制）
- 为什么十六进制要 2 位：1 位只有 16 种可能（0~15），而一个通道需要 256 种（0~255）；2 位 = 16 × 16 = **256** ✅
