# 任务四报告：文献库式文本分析工具

作者：Hou-cg
日期：2026-10-29

---

## 一、任务概述

做了一个"文献库"式的文本分析工具，用来快速浏览和筛选多篇文章：

- 可以**批量导入**多篇 `.txt` 文章（支持一次选多个 / 拖拽）
- 自动提取每篇的**关键词**和**核心句**
- 生成一个**可交互的 HTML 报告**：支持搜索、点击关键词屏蔽文章
- 支持**删除文章**、一键重新生成报告

**技术栈**：Flask（网页）+ jieba（中文分词）+ scikit-learn（TF-IDF）

**核心场景**：手上有 20 篇同方向的文献，一次性导入后，先用关键词和核心句快速扫一遍，再决定哪几篇需要细读。

## 二、使用方式

### 1. 环境

- Python 3.11（conda 虚拟环境 lab）
- 依赖：`flask`、`jieba`、`scikit-learn`

### 2. 安装依赖

```
pip install flask jieba scikit-learn -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3. 启动

```
conda activate lab
cd task4
python app.py
```

浏览器打开：**http://127.0.0.1:5000**

### 4. 需要的数据文件

- **`.txt` 纯文本文件**：每篇第一行是标题，其余为正文（UTF-8 或 GB18030 编码）
- 示例文本在 `samples/` 目录（6 篇）
- 运行时数据：
  - `library/` —— 存放导入的原始文章
  - `index.json` —— 存放元数据（标题、字数、关键词、导入时间）

## 三、实现思路

### 1. 整体流程

```
上传 .txt 文件
     ↓
analyzer.py：jieba 分词 → TF-IDF 关键词 → 抽取核心句
     ↓
写入 index.json + library/
     ↓
点"生成分析报告" → report.html（可搜索、可屏蔽）
```

### 2. 关键词提取

- 用 jieba 对中文分词
- 用 **TF-IDF** 计算每个词的权重
  （一个词在**某篇里频繁出现**、但在**所有文章里少见** → 权重高，说明它最能代表这篇的独特性）
- 取权重最高的 5 个作为该篇关键词

### 3. 核心句提取（抽取式摘要）

- 把文章切成句子
- 用同样的 TF-IDF 思路给每个句子打分
- 取分数最高的 2 句作为"核心句"
- **只挑原句，不做改写**

### 4. 筛选与屏蔽（两级）

| 层级 | 方式 | 特点 |
|---|---|---|
| **命令行** | `--include 词` / `--exclude 词` | 生成报告前过滤 |
| **报告页面内** | 搜索框实时过滤；点击关键词标签屏蔽文章 | **纯前端 JS，打开就能用，不用重新生成** |

### 5. 为什么把筛选做进 HTML

命令行参数需要记、需要敲，日常用起来麻烦。把筛选做进 HTML 里，打开页面就能操作，**工具才真正"可用"**，而不只是一个跑一次的脚本。

### 6. 文献库的设计

- 每篇文章有唯一 `id`，元数据存在 `index.json`
- **上传时立即分析一次**，之后打开列表直接读 `index.json`（**不用每次重新分析**）
- 删除时同时删 `library/` 里的文件和 `index.json` 里的记录
- 同名文件会跳过，不覆盖

## 五、遇到的困难与解决

| 现象 | 原因 | 解决 |
|---|---|---|
| 启动报 `ModuleNotFoundError: sklearn.__check_build._check_build` | 曾把一份**为 Python 3.9 编译**的 sklearn 复制进项目 `vendor/` 目录，与当前 3.11 环境不兼容 | 删除项目里的副本，改为用 pip 装到环境中。**教训：依赖库应该用包管理器安装，不要复制进项目目录** |
| 说"已支持多选"但实际只能选一个 | 只改了前端，后端仍按单个文件接收 | 前端加 `multiple` 并遍历拖拽的全部文件；后端改用 `request.files.getlist()`；并写自动测试脚本验证 |

## 六、局限（如实说明）

| 局限 | 说明 | 原因 |
|---|---|---|
| **核心句是"抽取"不是"生成"** | 只从原文挑句子，不做语义改写 | 生成式摘要需调用大语言模型 API（需联网 + 付费），本次未实现 |
| **单机单用户，不支持多用户隔离** | 所有人共用一份 `library/` 和 `index.json` | 要支持多人需增加账号系统、按用户划分数据目录，超出本次范围 |
| 只支持 `.txt` | 不支持 `.pdf` / `.docx` | 需要额外的解析库 |
| 关键词质量受分词影响 | 专业术语、新词可能分错 | 通用分词器的限制 |
| 无相似文章归并 | 每篇独立分析 | 未实现 |

## 八、AI 使用说明

### 1. AI 帮我做了什么

- 设计 Flask 应用结构与前端页面
- 生成 HTML / CSS / JS（卡片布局、搜索过滤、屏蔽交互）
- 写分析模块（jieba + TF-IDF）
- **我自己负责**：提出需求与方向（"文献库 + 增删"这个核心设计是我提的）、运行验证、判断结果是否正确

### 2. AI 出错的地方（如实记录）

**事件一：声称已支持多选，实际没做**
AI 回复"已支持多文件上传"，但页面上只能选一个文件。检查发现只加了前端标签，后端仍用单个文件接收。**要求它写自动测试脚本、用实际运行结果证明**之后，才真正修好。

**事件二：把依赖库复制进项目，导致启动失败**
AI 把一份为 Python 3.9 编译的 sklearn 复制进项目 `vendor/` 目录，与当前 Python 3.11 环境不兼容，导致 `ImportError`。**教训：依赖库应该用包管理器安装到环境中，不应该复制进项目目录。**

### 3. 我的做法

- **不接受"已完成"的口头结论**，要求提供实际运行结果或测试输出
- 每改一次，都**自己重启服务、重新操作一遍**验证
- AI 给出的方案先判断"是否真的解决了我的问题"，不合适就让它重做

## 九、一点思考：关于"技术只是一种工具"

做这个工具之前，我的想法很简单——"做个能跑的东西"。做出来之后才发现，**真正难的不是技术，而是想清楚"我到底要它解决什么问题"**。

比如"按关键词屏蔽文章"这个功能，它不是任何算法课上的内容，纯粹是因为我真实的需求是：**手上有 20 篇文献，我只想快速筛出其中几篇**。技术（jieba、TF-IDF、Flask）只是实现这个想法的**手段**；真正决定这个工具有没有价值的，是"我知道自己要什么"。

同样，**AI 也是手段**：它写代码比我快，但"做什么、不做什么、做到什么程度"这些判断必须我自己来做。而且——**当它说"做好了"的时候，我需要有能力判断真假**。

这一点在本次任务里体会特别深：它两次说"已完成"，实际上都没有完成。**技术可以外包，判断力不能。**
